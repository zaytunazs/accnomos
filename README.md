# Accnomos

**Accounting, intelligently done.** Bookkeeping and MTD VAT for UK small businesses, built for the Meta Global AI Developer Hackathon (Indie track).
Your books are files in your own OneDrive (no Accnomos database); Meta models read and check the paperwork; you approve; code calculates the VAT.

- **Works today (tested, mostly on fakes):** upload a receipt → Muse Glimmer 30B (or Muse Spark) reads it → code checks + an independent second reading → you approve → immutable ledger event → VAT nine boxes by code → HMRC **sandbox** submission (web) → `Books.xlsx`; plus Ask, bank statements, invoicing, jobs, mileage, pay-run estimates, a day planner and an Android app. One row each in the table below.
- **Not yet:** production HMRC filing, Google Drive, and any run of most features against a real OneDrive, a real model key or a real phone. `docs/HONESTY.md` lists every known gap.
- **Run it:** `uv sync --all-packages --all-extras && uv run pytest -q`; `cd apps/web && pnpm install && pnpm run build`; services and web dev servers in `docs/DEV.md`.
- **Docs:** [Architecture](docs/ARCHITECTURE.md) · [Meta models and evals](docs/META_MODELS.md) · [4-minute demo](docs/DEMO.md) · [Honesty](docs/HONESTY.md) · [What remains](docs/REMAINING.md)

## Layout

| Path | What |
|---|---|
| `apps/web` | Next.js PWA (Home · Review · Ask · Invoices · Bank · VAT return · Jobs · Payroll · Reports · Contacts · Vehicles · Files · Settings) |
| `apps/mobile` | Flutter Android app (Home · Review · Ask · VAT · More: Files, Contacts, Invoices, Jobs, Vehicles, Bank, Payroll, Reports, Audit trail; Settings), same runtime API — web parity in `apps/mobile/PARITY.md` (0.3.4+9) |
| `services/runtime` | Stateless Agent Runtime (FastAPI): receives the user's cloud token + AI config per request, keeps nothing |
| `services/hmrc-relay` | Stateless HMRC relay: holds the HMRC client secret, adds fraud-prevention headers |
| `packages/ledger` | Append-only ledger events, projections, deterministic VAT 9-box engine, bank CSV parsing and matching, tests |
| `packages/connectors` | `StorageProvider` / `MailProvider` / `ContactsProvider` / `CalendarProvider` interfaces, Microsoft Graph implementations, fake provider + contract tests |
| `evals` | Synthetic gold set and the eval harness that grades Meta model outputs |
| `tools` | Owner-run scripts (keystore, brand art, sample receipt, dev helpers) |
| `docs` | `ARCHITECTURE.md` (folder layout, headers, models, audit format), `DEV.md`, `HMRC.md`, `AUTOPILOT.md`, `ACTIONS.md`, `INBOX.md`, `PLANNER.md`, `SECURITY.md`, `HONESTY.md`, `REMAINING.md`, `PRODUCTION.md` (going live), `reviews/` |

## Meta models used (runtime path)

| Model | Role |
|---|---|
| Muse Glimmer 30B (open weights, Ollama) | Receipt/invoice reading, categorising, local-mode Ask, Verifier and the other text tasks |
| muse-spark-1.3 (Meta Model API, user's key) | Key-mode extraction, Ask and the other text tasks |
| Muse Spark Open (Baseten, optional) | Independent verifier (key mode; needs the server owner's Baseten key; unit-tested only) |
| muse-voice-transcribe-1.0 | Spoken questions on Ask (key mode; not yet run live) |
| sam-3.1 | Crop receipts in messy photos, **off by default** (code crop is the default; never run live) |

Muse Image made the brand artwork at build time (`tools/brand_muse.py`; not in the runtime). Costs, fallbacks and eval numbers: `docs/META_MODELS.md`.

## Invoicing

Money is code's job: each line's net is quantity × unit price and its VAT is worked out per line at the VAT code's
rate (S 20%, R 5%, Z 0%, E exempt, O outside the scope), each rounded half up to the penny; the VAT summary and
totals are sums of lines, and whatever totals a client sends are ignored. Only drafts can be changed; numbers are
never reused (an unwanted draft is voided, not deleted). Sending emails first, then marks the invoice sent, then
posts the sale with an id derived from the invoice number, so a retry never emails twice or posts twice. An
invoice can only charge VAT once your VAT registration number is in the profile. Reminders are drafts: nothing is
sent without your confirmation, and the AI never sees your bank details (it says they are on the attached
invoice). Marking paid posts nothing (as with bank matching, the receipt is not yet posted to 1200 Bank); a paid
invoice cannot be voided, and credit notes are not built yet.


## Outlook intake

Turn it on in Settings and Accnomos asks Microsoft for one extra permission, `Mail.Read` (read-only). *Check my inbox
now* looks at emails from the last 14 days and, with plain code (no AI), keeps PDF/JPEG/PNG/HEIC attachments
between 10 KB and 25 MB that look like receipts or invoices (sender outside your own domain; words such as receipt,
invoice, bill, order, payment, VAT or remittance in the subject or file name); a HEIC photo is saved as a JPEG. An email
with **no attachment** whose subject or preview mentions a receipt, order, trip, payment and the like has its body read
as plain text, and is kept when a total, VAT, invoice or receipt label is followed by a currency amount (Uber-, Amazon-
and SaaS-style receipts); marketing senders and sale subjects are skipped. **Read:** message date, sender, subject,
those attachments and those bodies. **Written, all in your own folder:** the file as
`00 Inbox/<date>_<sender-domain>_<name>` (a body as `<date>_<sender-domain>_<subject>.eml.txt`),
`_System/Intake/seen.json` (so nothing is copied twice) and `_System/Intake/log/<yyyy-mm>.jsonl`. **Never:** sending,
moving, flagging, marking as read or deleting mail, or keeping anything on our server. The last check time is kept only
in this browser. What happens to each format after that: `docs/INBOX.md`.

## Verifier (second opinion)

When the first reading passes every code check, a Verifier model reads the same image again with a different prompt
(one question per field) and never sees the first answer. Code then compares supplier, VAT number, date, net, VAT
and total: names ignoring case, punctuation and Ltd/Limited, dates by value, money to the penny (±1p), VAT numbers
by digits. If all six agree, the Review card says *Verifier agrees · all 6 fields match*. Any disagreement sends the
proposal to *Needs a look* with both readings side by side; check the document, then approve or reject. Neither the
model nor the code picks or merges values (choosing the second reading in the card is not built yet). **Which
model:** in local mode it is Glimmer on your machine, so the document stays there. With your own key it is Muse Spark
Open on Baseten if the server owner has set `BASETEN_API_KEY`, otherwise muse-spark-1.3 with your key.
`VERIFIER=off` disables it. First numbers (20 messy receipts, Glimmer/Glimmer): 94% full agreement, 0 errors caught
beyond what the code checks already caught, 1 false alarm. See `evals/REPORT_verifier_glimmer_messy_20_2026-10-27.md`.
Not built: Google Drive (OneDrive only), production HMRC filing, `muse-wonder` multi-step planning, credit notes, RTI.
